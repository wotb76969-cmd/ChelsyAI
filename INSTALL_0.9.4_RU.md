# Установка испытательной версии Chelsy AI 0.9.4

## 1. Распаковка

Скачайте ZIP проекта по ссылке в PR. В Windows нажмите правой кнопкой по архиву → «Извлечь всё» и выберите новую папку. В Linux выполните `unzip имя-архива.zip -d chelsy-test`. Откройте извлечённый каталог с файлами `install_host.py` и `AGENTS.md`. Команды ниже выполняются из него. Оставьте действующую установку и её данные в отдельном каталоге.

В архиве находятся исходники, небольшой адаптер, сайт и примеры документов. Вложенный `distribution/ChelsyGroup_Web_0.9.4.zip` нужен только для отдельного размещения сайта. В нём файлы лежат от корня, рядом находится манифест SHA-256. Для установки из полного архива сайт уже распакован в `ChelsyGroup_Web`.

## 2. Подготовка Host

Для основного варианта нужны Python 3.11 или 3.12, работающий Docker с Linux-контейнерами для создания документов и Ollama с уже установленной текстовой моделью на Host. Проверка: `docker version` и `ollama list`. Имя нужной модели возьмите из второго вывода. Для HTTPS понадобится Caddy 2.10 или совместимый. Клиенты подключаются к Host по сети.

Следующая команда устанавливает зависимости в локальную `.venv` и собирает изолированный обработчик документов. При первой установке нужны интернет для образа и пакетов и свободное место на диске. Выполняйте её на выделенном испытательном компьютере при согласии на установку.

**Windows, PowerShell**

```powershell
py -3.11 install_host.py --runtime ollama --state "$env:LOCALAPPDATA\Chelsy094-Test"
$env:CHELSY_DATA_DIR = "$env:LOCALAPPDATA\Chelsy094-Test\data"
$env:CHELSY_MODEL = Read-Host "Имя установленной модели Ollama"
```

**Linux**

```bash
python3 install_host.py --runtime ollama --state "$HOME/.local/share/chelsy094-test"
export CHELSY_DATA_DIR="$HOME/.local/share/chelsy094-test/data"
read -rp 'Имя установленной модели Ollama: ' CHELSY_MODEL
export CHELSY_MODEL
```

Для работы с собственным адаптером вместо Ollama предусмотрен явный режим `--runtime adapter`. Он устанавливает CPU PyTorch, Transformers и PEFT, скачивает около 1 ГБ базовых весов с фиксированной ревизии и проверяет SHA-256. Выбирайте его только после согласования загрузки. Задайте `CHELSY_LOCAL_BASE` равным абсолютному пути к подкаталогу `base` выбранного каталога состояния и перезапустите Host. `CHELSY_BASE_ONLY=1` переключает этот же путь на исходную модель для сравнения. Удаление этой переменной возвращает адаптер при следующем старте.

## 3. Первый вход

В Windows выполните команды ниже. В Linux замените `.\.venv\Scripts\python.exe` на `./.venv/bin/python` и используйте прямые слеши в путях. Значение `CHELSY_DATA_DIR` должно быть одинаковым во всех терминалах Host.

```powershell
.\.venv\Scripts\python.exe ChelsyAI_0.9_Windows\configure_accounts.py admins
.\.venv\Scripts\python.exe ChelsyAI_0.9_Windows\configure_accounts.py user
.\.venv\Scripts\python.exe ChelsyAI_0.9_Windows\host_server.py
```

Первая команда первоначальной настройки создаёт сразу двух администраторов. Укажите два адреса и отдельные пароли длиной от 15 символов. Вторая создаёт обычный аккаунт. Его владелец меняет первоначальный пароль в кабинете. Третья запускает Host. В другом терминале откройте `http://127.0.0.1:8787/api/v3/health` и проверьте `ok: true`. Локальная панель управления запускается тем же Python командой `ChelsyAI_0.9_Windows/admin_panel.py`.

## 4. HTTPS и клиенты

Укажите в DNS собственный домен с входящим публичным адресом. Для домашней сети проверьте проброс порта 443 и возможность получения сертификата Caddy. При CGNAT понадобится доступный IPv6 или публичный адрес провайдера. Host и Ollama слушают loopback. Наружу публикуется только HTTPS через обратный прокси.

В терминале Caddy задайте `CHELSY_DOMAIN` равным вашему домену, `CHELSY_WEB_ROOT` — абсолютному пути к распакованной папке `ChelsyGroup_Web`. Для PowerShell используйте синтаксис `$env:CHELSY_DOMAIN = "ваш.домен"`, для Bash — `export CHELSY_DOMAIN=ваш.домен`. Запустите `caddy run --config deploy/Caddyfile` из корня проекта. Если Caddy установлен как служба, передайте обе переменные службе и дайте ей право читать папку сайта.

Откройте `https://ваш.домен/login.html`. В разделе «Мои задачи» отправьте короткий вопрос или опишите документ. Готовый документ появится в «Мои файлы». В нативных клиентах укажите тот же HTTPS-адрес. Сборщики Windows находятся в `ChelsyAI_0.9_Windows/BUILD_INSTALLER.ps1`, Android — в `Android_Client/BUILD_ANDROID_APK.bat`. Инструкция по Xcode и подписи — в [руководстве iOS](iOS_Client/README_0.9.4_RU.md). Статус конкретных сборок приведён в [сводке испытаний](ACCEPTANCE_0.9.4_RU.md).

## 5. Данные, обновление и откат

Для первой пробы используйте пустой каталог данных. Перед обновлением остановите Host, сохраните старую версию приложения и сделайте резервную копию данных на защищённом диске. В отдельном виртуальном окружении Host выполните следующие команды, подставив свои пути. Первая просит отдельный пароль копии, вторая проверяет её и восстанавливает данные в **новую** папку.

```text
python ChelsyAI_0.9_Windows/backup_private.py pack КАТАЛОГ_ДАННЫХ ПУТЬ_К_НОВОЙ_КОПИИ
python ChelsyAI_0.9_Windows/backup_private.py restore ПУТЬ_К_КОПИИ НОВЫЙ_КАТАЛОГ
```

Сохраните пароль резервной копии отдельно. Восстановление пользовательского ключа для чтения старого содержимого требует секрета пользователя. Настройки DNS, Caddy, почты, сертификаты и ключи подписи сохраняйте отдельно защищённым способом. Архиватор исключает вложенный каталог предыдущих резервных копий.

Для пробного переноса учётных записей используйте `transfer_accounts.py --source-db ... --accounts ... --staged-db ...`. Нужен разрешённый JSON-экспорт с UUID, email и совместимыми bcrypt-хешами, а также локальная SQLite с уже перенесёнными сообщениями. Команда создаёт отдельную БД. Облачные сообщения, которых ещё нет в SQLite, требуют отдельного экспорта и сверки. До переключения проверьте UUID, количество записей и доступ под владельцем. Для отката остановите новый Host, отдельно сохраните записи, поступившие после переключения, и укажите старой версии каталог восстановленной копии соответствующей схемы.
